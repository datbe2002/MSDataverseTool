01

Ý tưởng cốt lõi

App hiện tại gửi thẳng SQL tới TDS endpoint nên bị bó theo những gì endpoint đó expose. SQL 4 CDS thì có engine riêng và định tuyến từng phần truy vấn sang con đường phù hợp:

SQL text → AST → logical plan → FetchXML / Web API (đọc) & SDK messages (ghi) → thực thi → chuẩn hóa rows

Vì virtual entity và bảng đặc biệt đều đọc được qua FetchXML / RetrieveMultiple, chỉ cần có con đường FetchXML là tự nhiên query được chúng. TDS chỉ còn là đường tăng tốc tùy chọn cho bảng chuẩn.

03

Pipeline truy vấn

1
Parse
SQL → AST bằng sqlparser-rs (hoặc parser của engine).
2
Bind & validate
Khớp bảng/cột với metadata Dataverse — dùng lại cache EntityDefinitions / Attributes app đã có; xử lý lookup, option-set, alias.
3
Plan & route
Bảng chuẩn + phép đơn giản → TDS (nhanh); virtual entity, bảng non-report, ghi, metadata → FetchXML / Web API.
4
Execute
Chạy FetchXML qua Web API (?fetchXml=) với paging cookie (5000/trang); phần FetchXML không diễn đạt được → xử lý in-memory.
5
Return
Chuẩn hóa kiểu dữ liệu, format lookup / option-set → về đúng QueryResult hiện tại của app.
04

Lộ trình theo giai đoạn

0

Spike & chốt engine ~vài ngày

Prototype hướng A (một SELECT đơn giản → FetchXML → rows) và hướng B (gọi SQL4CDS qua sidecar). Đo effort / bundle / độ trễ rồi chọn.

1

Fallback đọc 1 bảng MVP parity — bắt đầu ở đây

SELECT cols FROM table [WHERE …] [ORDER BY] [TOP] → FetchXML. Route: TDS báo "not available for reports" hoặc bảng ảo → tự chuyển FetchXML. Đây là thứ mở khóa agenttask, activityfileattachment ngay.

2

JOIN & aggregate

JOIN theo quan hệ → link-entity; GROUP BY / aggregate → FetchXML aggregate; cái nào FetchXML chịu thua thì xử lý in-memory.

3

Lớp engine in-memory

Nếu chọn DataFusion, phần này gần như miễn phí — nó lo join / aggregate / subquery / union và đẩy filter xuống FetchXML. Thêm bảng ảo metadata.entity / metadata.attribute.

4

Ghi & nâng cao đã có nền

Mở rộng INSERT / UPDATE / DELETE → Web API (app đã làm phần này); thêm SELECT INTO, gọi Dataverse Action…

5

Polish

Auto-route TDS ↔ FetchXML, xem trước query plan (hiện FetchXML sẽ chạy), song song hóa paging, format lookup/option-set, xử lý lỗi.
